# Xinyue AI 前台、画布、后台与计费优化完成说明

更新时间：2026-08-27

## 1. 本轮边界

- 保留用户端主导航、页面布局、核心工作流和视觉方向。
- 保留无限画布的全屏编辑器、左侧工具、中央画布及右侧 Agent/属性区。
- 保留管理端业务路由、资源 key、角色权限和审计能力，只整理查找方式与代码所有权。
- 新结构直接替换旧结构，不保留双组件、双 API、双字段读取或长期版本兼容分支。
- 新增内容仅用于补齐已有业务所需的 Token 计量、成本核算和异常对账。

## 2. 用户端优化

| 区域 | 完成内容 | 用途 |
| --- | --- | --- |
| 思考与回复 | 统一 `thinking/search/reasoning/answer/done` 状态，消息组件只渲染明确状态 | 防止思考、联网搜索、推理和正文互相覆盖 |
| 消息导航 | 抽离定位、高亮、自动滚动、会话切换清理 | 避免历史消息导航和流式滚动互相影响 |
| 聊天提交 | 统一鉴权、意图识别、模型检查、聊天/图片/视频分流及草稿失败恢复 | 保证提交失败后输入、附件和来源不丢失 |
| 生成状态 | 图片、视频、商品图共用活动、终态、失败、停止和重试规则 | 消除不同页面对同一任务状态的不同判断 |
| 文件上传 | 聊天附件、参考图、蒙版和文件库使用同一上传实现 | 统一文件限制、进度和错误处理 |
| 模型目录 | 请求去重、缓存、默认选择和刷新使用同一实现 | 防止切换能力时重复请求或选择不存在的模型 |
| 会话生命周期 | 集中模型同步、助手默认模型、流式自动滚动等 watcher | 降低 `StudioPage.vue` 的交叉状态风险 |

关键文件：

- `src/utils/chat-response-state.ts`
- `src/utils/generation-run-state.ts`
- `src/composables/chat/`
- `src/composables/studio/`

## 3. 无限画布优化

| 区域 | 完成内容 | 用途 |
| --- | --- | --- |
| 历史 | 抽离撤销、重做、复制、粘贴和历史上限 | 让节点编辑与历史栈解耦 |
| 保存 | 抽离自动保存、并发保存、脏状态和离开提醒 | 避免旧响应覆盖新文档，保证离开前提示准确 |
| 生成监控 | 抽离流式监控、轮询回退、取消和失败状态 | 统一画布节点的生成生命周期 |

## 4. 管理端优化

| 区域 | 完成内容 | 用途 |
| --- | --- | --- |
| 导航与搜索 | 支持业务别名、父级业务域、资源 key 和路由名搜索，结果展示所属业务域 | 管理员可按“Token 定价、BYOK、会员、生成记录”等概念直接找功能 |
| 运营资源页 | 抽离资源类型、状态/媒体/日期格式化、编辑值映射和 payload 转换 | 降低二十多类资源在单页中的条件分支密度 |
| 设置中心 | 抽离保存字段白名单、默认聊天内容、公开页归一化和敏感凭据载荷 | 防止修改一个设置面板时意外提交其他内部字段 |
| API 所有权 | 删除 `admin/src/api/xinyue.ts`，改为客户、模型、订阅、支付、治理、内容、设置等业务 API | 页面只依赖所属业务，不再通过千行聚合入口调用所有接口 |
| 一致性 | 复用现有 Element Plus、状态标签和表格壳 | 不新增另一套后台视觉或嵌套卡片体系 |

业务 API 位于 `admin/src/api/xinyue/`。运营页辅助模块位于 `admin/src/views/xinyue/operations/`。

## 5. Token、会员与计费

项目原有能力已经包括价格版本、价格快照、创作点账户与账本、会员套餐、用户组倍率、Token 预授权、实际结算退款、毛利报表和支付对账。本轮没有重复建设第二套系统，而是补齐以下缺口：

| 能力 | 完成内容 | 用途 |
| --- | --- | --- |
| 协议用量 | 统一解析 OpenAI、Anthropic、Gemini 的输入、输出、缓存和推理 Token | 中转渠道返回不同字段时仍得到一致用量 |
| 流式用量 | 修复 Anthropic 分段事件可能用输出事件的 `0` 覆盖输入用量 | 避免 Token 少计和成本少计 |
| 任务明细 | `GenerationJob` 新增 `cachedInputTokens`、`reasoningTokens` | 保留供应商用量细分用于报表和核查 |
| 经营报表 | 用量报告和毛利报告增加缓存、推理 Token 汇总 | 管理员可以看到真实模型消耗结构 |
| 异常对账 | 新增任务、供应商用量、个人/团队账本、退款四方核对 | 发现漏扣、漏退、净扣不一致和成本快照不一致 |
| 管理入口 | 商业化下新增“异常账单”，复用运营表格与详情抽屉 | 集中查看严重和警告账单，不改变后台页面结构 |

异常对账接口：`GET /v1/admin/finance/reconciliation?days=30`。

数据库迁移：`server/prisma/migrations/20260827100000_generation_usage_breakdown/migration.sql`。

## 6. 已删除的旧实现

- 删除管理端聚合 API `admin/src/api/xinyue.ts`，没有保留转发层。
- 删除提示词源 `legacyDisplayNames` 历史名称读取，只认当前后台配置名称。
- 用户端、画布和管理端拆分后，页面不再保留被抽离逻辑的旧副本。
- 数据库字段与服务端、报表、管理端在同一版本切换，没有双字段兼容读取。

网络请求的备用上游、生成轮询回退和默认值容错属于运行可靠性，不属于旧版本兼容，继续保留。

## 8. 上线后运维

上线前执行 `npm --prefix server run prisma:deploy`。上线后主要关注：

1. 在“模型与定价”维护各模型输入、输出费率及价格版本。
2. 在“成本与毛利”观察模型和渠道成本结构。
3. 在“异常账单”优先处理严重项，再核查供应商未返回用量的警告项。
4. 套餐、用户组倍率或创作点价值调整时发布新价格版本，不回写历史任务价格快照。
